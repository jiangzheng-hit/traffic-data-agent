# 项目面试讲解

## 三十秒版本

我把交通数据课程作业升级成了一个本地AI Native数据治理助手。用户选择预测目标并描述需求后，Agent会先做数据画像、目标泄漏和冗余诊断，再生成受约束的处理计划。用户确认后，系统调用Python工具完成清洗、验证和建模。项目最重要的发现是拥堵标签与速度阈值完全一致：包含泄漏字段时决策树得到100%指标，排除后明显下降，说明高分不一定可信。系统因此把Agent定位为建模风险诊断者，而不是一键刷分工具。

## 两分钟版本

原课程项目包含726条、22字段的15分钟粒度交通数据，任务是清洗、回归和拥堵分类。我重构时没有直接套一个聊天框，而是先把数据画像、清洗、特征、验证和建模拆成独立工具。

然后我增加了目标泄漏诊断。系统会对二分类目标搜索单字段阈值规则，同时结合字段语义检查。它发现`speed_kmh <= 34.5`可以100%复现`is_congested`，因此将速度和拥堵等级标记为高风险字段。使用同一种决策树做对照时，包含泄漏字段的指标达到100%，排除以后下降到合理范围。

Agent层有规则规划器和可选的Ollama本地规划器。大模型只生成JSON计划，执行器只开放白名单工具。即使大模型尝试删除验证步骤或重新加入泄漏字段，安全合并层也会恢复强制约束。Ollama不可用时自动回退规则规划器，所以演示不会被模型服务阻塞。

在最终基线上，我排除泄漏字段并按时间顺序划分训练、验证和测试集，只用验证集比较Logistic、SVM和决策树，选定逻辑回归后才评估测试集，得到Accuracy 93.75%、Recall 98.55%。系统同时导出清洗数据、执行计划、日志、指标、图表和HTML报告。

## 常见追问

### 为什么叫AI Native

AI参与的是目标理解和计划生成，而不是写一段总结。计划会驱动实际工具执行，工具结果又决定是否允许进入下一阶段，形成观察、规划、执行、验证和反馈闭环。

### 为什么不用大模型直接写Pandas代码

任意代码执行不可控，也难以审计。白名单工具能够保证参数、数据变化和结果都有明确记录，更适合数据治理场景。

### 为什么时间划分比随机划分更合理

交通预测通常使用过去数据预测未来。随机划分会把相邻时间模式同时放进训练和测试集，可能高估泛化能力。时间划分更接近实际使用方式。

### 质量评分是不是科学标准

不是行业统一标准。它是项目内的治理优先级指标，用于把重复、缺失、泄漏和冗余风险汇总展示，报告中明确说明了这一限制。

### 项目还有什么不足

数据量较小且时间跨度只有约一周。当前异常检测规则主要针对通用交通字段，真实部署需要跨道路、跨季节数据、漂移监控和外部验证。

## 不要说的话

- 不要说这是生产级交通平台。
- 不要说模型可以直接用于道路管理。
- 不要把课程提供的数据说成真实企业数据。
- 不要只强调模型分数，要强调发现并控制泄漏风险。
